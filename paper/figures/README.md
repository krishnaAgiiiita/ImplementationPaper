# Interpretation Guide: Scientific Citation-Support and Citation-Drift Charts

This document explains the six visualizations generated by the
scientific citation-support and citation-drift verification experiment.
Each chart compares the ground-truth labels and/or the predictions
produced by the lexical Jaccard baseline and the pretrained
Cross-Encoder Natural Language Inference (NLI) model.

## Experimental label convention

All charts use the following standardized class labels:

  ------------------------------------------------------------------------
                      Label ID Class name            Meaning
  ---------------------------- --------------------- ---------------------
                             0 `CONTRADICT`          The cited evidence
                                                     contradicts the
                                                     scientific claim.

                             1 `NO_EVIDENCE`         The cited evidence
                                                     does not provide
                                                     annotated support or
                                                     contradiction; in the
                                                     SciTail fallback this
                                                     corresponds to
                                                     neutral.

                             2 `SUPPORT`             The cited evidence
                                                     supports or entails
                                                     the scientific claim.
  ------------------------------------------------------------------------

The chart order is consistently `CONTRADICT`, `NO_EVIDENCE`, and
`SUPPORT`.

> **Interpretation caveat:** In the SciFact extraction procedure, a
> cited document without an evidence annotation is operationally
> assigned `NO_EVIDENCE`. An absent annotation does not necessarily
> prove that the document is semantically neutral. If SciTail is used as
> the fallback dataset, it provides only neutral and entailment classes;
> it does not provide contradiction examples. These dataset
> characteristics must be disclosed when interpreting the results.

## 01. `01_dataset_class_distribution.png` --- Ground-Truth Dataset Class Distribution

### What the chart represents

This chart displays the number of evaluation samples belonging to each
ground-truth class:

-   `CONTRADICT`
-   `NO_EVIDENCE`
-   `SUPPORT`

The horizontal axis represents the class labels, while the vertical axis
represents the number of claim-document pairs in each class.

### How the values are calculated

For class (c), its sample count is:

\[ N_c = `\sum`{=tex}\_{i=1}\^{N} `\mathbb{1}`{=tex}(y_i=c) \]

where:

-   \(N\) is the total number of evaluation samples.
-   (y_i) is the ground-truth label of sample (i).
-   (`\mathbb{1}`{=tex}(`\cdot`{=tex})) is the indicator function, equal
    to 1 when the condition is true and 0 otherwise.

The percentage of samples belonging to class (c) is:

\[ P_c = `\frac{N_c}{N}`{=tex}`\times 100`{=tex} \]

### Why this chart is important

Class distribution is essential for understanding the evaluation
conditions. A dataset with many `SUPPORT` examples but very few
`CONTRADICT` examples is imbalanced.

A classifier may achieve apparently good overall performance by
predicting the majority class frequently, while performing poorly on the
less common classes. This is one reason the experiment reports Macro-F1
in addition to per-class metrics.

### How to interpret it

-   Similar bar heights indicate a relatively balanced evaluation set.
-   A substantially taller bar indicates a dominant class.
-   A very short or absent bar indicates that the corresponding class
    has few or no test examples.

If a class has zero ground-truth samples, its precision, recall, and F1
results require careful interpretation. In particular, recall for a
class with no ground-truth examples is not empirically estimable from
that evaluation set.

### Research significance

This chart provides the class-frequency context needed to interpret all
subsequent performance charts. It should be included when reporting
results so readers can assess whether class imbalance may influence the
comparison.

## 02. `02_macro_f1_comparison.png` --- Macro-Averaged F1-Score Comparison

### What the chart represents

This chart compares the Macro-F1 scores of the two evaluated systems:

1.  **Jaccard lexical baseline:** Uses token overlap between the claim
    and evidence.
2.  **Cross-Encoder NLI:** Uses a pretrained transformer to classify the
    semantic relationship between the evidence and the claim.

The vertical axis represents Macro-F1, with values between 0 and 1. A
higher value indicates better classification performance under the
Macro-F1 metric.

### How Macro-F1 is calculated

For each class (c), precision and recall are:

\[ Precision_c = `\frac{TP_c}{TP_c+FP_c}`{=tex} \]

\[ Recall_c = `\frac{TP_c}{TP_c+FN_c}`{=tex} \]

The class-specific F1-score is:

\[ F1_c = 2`\cdot`{=tex} `\frac{Precision_c\cdot Recall_c}`{=tex}
{Precision_c+Recall_c} \]

Macro-F1 is the unweighted arithmetic mean of the F1-scores across the
three standardized classes:

\[ Macro`\text{-}`{=tex}F1 = `\frac{F1_{\text{CONTRADICT}}+
F1_{\text{NO\_EVIDENCE}}+
F1_{\text{SUPPORT}}}{3}`{=tex} \]

The implementation uses `zero_division=0` when a metric is undefined
because a class has no relevant predictions or examples.

### Why this chart is important

Macro-F1 gives equal weight to each class, rather than allowing the most
frequent class to dominate the aggregate score. It is therefore useful
when the dataset is imbalanced and all three citation relationships
matter.

### How to interpret it

-   A higher Cross-Encoder bar indicates better Macro-F1 on the
    evaluated sample.
-   A higher Jaccard bar indicates that lexical overlap performed better
    under this particular evaluation.
-   Similar bars indicate comparable aggregate performance, although the
    systems may still have very different per-class error patterns.

The difference can be expressed as:

\[ `\Delta `{=tex}F1 =
Macro`\text{-}`{=tex}F1\_{`\text{Cross-Encoder}`{=tex}} -
Macro`\text{-}`{=tex}F1\_{`\text{Jaccard}`{=tex}} \]

A positive value favors the Cross-Encoder; a negative value favors
Jaccard.

### Important limitation

The Jaccard baseline is intentionally unable to predict `CONTRADICT`. It
predicts only `SUPPORT` when token overlap exceeds the threshold and
otherwise predicts `NO_EVIDENCE`. Its contradiction recall is therefore
zero whenever contradiction examples occur in the test set.

### Research significance

This chart provides a compact headline comparison between lexical
matching and semantic NLI classification. It should not be interpreted
alone: the per-class metrics and confusion matrices are needed to
identify which relationships account for the difference.

## 03. `03_per_class_metrics.png` --- Per-Class Precision, Recall, and F1-Score Comparison

### What the chart represents

This chart breaks classification performance down by ground-truth class
and evaluation metric.

For each of the three classes, it displays:

-   Precision
-   Recall
-   F1-score

The chart includes separate metric bars for each evaluated system. It
therefore shows whether a system performs consistently across the three
citation relationships.

### Definitions

**Precision** measures the proportion of predictions assigned to a class
that are correct:

\[ Precision_c = `\frac{TP_c}{TP_c+FP_c}`{=tex} \]

High precision means that predictions of class (c) are usually reliable.

**Recall** measures the proportion of ground-truth examples of a class
that the model successfully identifies:

\[ Recall_c = `\frac{TP_c}{TP_c+FN_c}`{=tex} \]

High recall means that the model misses relatively few examples
belonging to class (c).

**F1-score** is the harmonic mean of precision and recall:

\[ F1_c = 2`\cdot`{=tex} `\frac{Precision_c\cdot Recall_c}`{=tex}
{Precision_c+Recall_c} \]

### Why this chart is important

Two systems can have similar Macro-F1 scores while exhibiting
substantially different behavior for individual classes.

For citation verification, the distinction is important:

-   Low `CONTRADICT` recall means contradictory evidence is frequently
    missed.
-   Low `NO_EVIDENCE` precision means many examples predicted as neutral
    are actually support or contradiction cases.
-   Low `SUPPORT` precision means the system may incorrectly treat
    insufficient or contradictory evidence as support.

### How to interpret it

Examine the three metrics for each class together:

-   **High precision, low recall:** Predictions for the class are
    trustworthy, but the system misses many true examples.
-   **Low precision, high recall:** The system identifies many true
    examples but also produces many false positives.
-   **High precision and high recall:** The system performs well for
    that class.
-   **Low F1:** The combined precision-recall performance is weak.

For citation-drift analysis, pay particular attention to `CONTRADICT`
recall and `SUPPORT` precision. These help reveal whether the system
misses contradictions or makes unsupported support predictions.

### Important limitation

If the evaluation data contains no examples of a class, its metrics may
be zero or otherwise uninformative under the configured reporting
convention. For SciTail, contradiction performance cannot be evaluated
because the fallback dataset does not contain contradiction examples.

### Research significance

This chart identifies the class-specific strengths and weaknesses hidden
by an aggregate score. It is especially useful for explaining whether a
semantic model improves contradiction detection, support recognition,
neutral classification, or some combination of them.

## 04. `04_confusion_matrices_counts.png` --- Confusion Matrices (Raw Classification Counts)

### What the chart represents

This chart displays one confusion matrix for each evaluated system. It
compares the ground-truth class against the predicted class using
absolute sample counts.

The matrix convention is:

-   **Rows:** Ground-truth labels.
-   **Columns:** Predicted labels.
-   **Diagonal cells:** Correct classifications.
-   **Off-diagonal cells:** Misclassifications.

The class ordering is:

1.  `CONTRADICT`
2.  `NO_EVIDENCE`
3.  `SUPPORT`

### Mathematical definition

For a three-class classification problem, the confusion matrix (C) is:

\[ C\_{ij} = `\sum`{=tex}\_{k=1}\^{N} `\mathbb{1}`{=tex}(y_k=i
`\land `{=tex}`\hat{y}`{=tex}\_k=j) \]

where:

-   (y_k) is the ground-truth label.
-   (`\hat{y}`{=tex}\_k) is the predicted label.
-   \(i\) identifies the ground-truth class.
-   \(j\) identifies the predicted class.

### How to interpret it

The diagonal cells contain correct predictions:

-   `CONTRADICT` → `CONTRADICT`
-   `NO_EVIDENCE` → `NO_EVIDENCE`
-   `SUPPORT` → `SUPPORT`

The off-diagonal cells identify the types of errors.

Examples:

-   Ground truth `CONTRADICT`, predicted `SUPPORT`: contradictory
    evidence is incorrectly treated as support.
-   Ground truth `SUPPORT`, predicted `NO_EVIDENCE`: supporting evidence
    is missed.
-   Ground truth `NO_EVIDENCE`, predicted `SUPPORT`: evidence without
    annotated support is incorrectly treated as supporting.

### Why this chart is important

Raw counts reveal the absolute number of errors. They are useful for
auditing the actual predictions and identifying which error types
contribute most to the total mistakes.

For example, a cell containing 12 means that 12 evaluation samples
belonging to the row's ground-truth class were assigned to the column's
predicted class.

### Research significance

This visualization is useful for identifying directional
citation-verification errors. In particular, the `CONTRADICT` →
`SUPPORT` cell is important because it represents the most direct form
of contradiction-to-support misclassification in this label scheme.

However, raw counts are influenced by class frequency. Use the
row-normalized confusion matrix as a complementary view.

## 05. `05_confusion_matrices_row_normalized.png` --- Row-Normalized Confusion Matrices (Class-Conditional Prediction Rates)

### What the chart represents

This chart displays the same confusion matrices as Chart 04, but each
ground-truth row is normalized by its row total.

Consequently, each non-empty row sums to 1, or 100%.

It expresses the proportion of examples in a ground-truth class that
were assigned to each predicted class.

### How normalization is calculated

Let (C) be the raw confusion matrix. The row-normalized matrix (R) is:

\[ R\_{ij} = `\frac{C_{ij}}{\sum_{j}C_{ij}}`{=tex} \]

provided that the ground-truth row has at least one example.

In percentage form:

\[ R\_{ij}\^{(%)} =
`\frac{C_{ij}}{\sum_{j}C_{ij}}`{=tex}`\times100`{=tex} \]

A row with no ground-truth examples has no defined distribution; the
implementation displays zeros for that row.

### How to interpret it

Consider the following hypothetical row for the `CONTRADICT` class:

  Predicted class     Row-normalized value
  ----------------- ----------------------
  CONTRADICT                          0.80
  NO_EVIDENCE                         0.10
  SUPPORT                             0.10

This means:

-   80% of contradictory examples were correctly identified.
-   10% were classified as `NO_EVIDENCE`.
-   10% were incorrectly classified as `SUPPORT`.

The diagonal value in each row is the recall for that ground-truth
class.

### Why this chart is important

Unlike raw confusion counts, row normalization controls for the number
of examples in each ground-truth class. It makes it easier to compare
class-conditional error rates between systems when the dataset is
imbalanced.

For citation-drift analysis, inspect these transitions carefully:

  -----------------------------------------------------------------------
  Ground-truth class      Predicted class         Interpretation
  ----------------------- ----------------------- -----------------------
  CONTRADICT              SUPPORT                 Contradictory evidence
                                                  is incorrectly accepted
                                                  as support

  SUPPORT                 NO_EVIDENCE             Supporting evidence is
                                                  not recognized

  NO_EVIDENCE             SUPPORT                 Lack of annotated
                                                  support is classified
                                                  as support

  NO_EVIDENCE             CONTRADICT              Neutral or unannotated
                                                  evidence is classified
                                                  as contradiction
  -----------------------------------------------------------------------

### Research significance

This is one of the most useful charts for analyzing the direction of
classification errors. It reveals not only how often a model is wrong,
but also how each ground-truth class is distributed across the predicted
classes.

It is particularly valuable when comparing models on imbalanced data.

> **Terminology note:** Row-normalized confusion values are
> class-conditional prediction proportions. They should not be confused
> with prediction confidence or calibrated probabilities. The chart is
> based on hard class predictions, not the model's softmax
> probabilities.

## 06. `06_latency_comparison.png` --- Amortized Inference Latency Comparison

### What the chart represents

This chart compares the average measured inference latency per sample
for each evaluated system.

The systems are:

1.  Jaccard lexical baseline.
2.  Cross-Encoder NLI model, when transformer inference completes
    successfully.

The vertical axis is measured in milliseconds per sample.

### How latency is calculated

For a system evaluating (N) samples, let (T\_{`\text{total}`{=tex}}) be
the measured total execution time in milliseconds.

The amortized latency per sample is:

\[ T\_{`\text{sample}`{=tex}} = `\frac{T_{\text{total}}}{N}`{=tex} \]

For the Jaccard baseline, the implementation measures each sample
individually and also measures total elapsed time.

For the Cross-Encoder, inference is batched. The measured interval
includes tokenization and model forward inference across the batches.

### Why amortized latency is used

The Cross-Encoder processes several samples together, rather than
invoking the model separately for every pair. Its total batch execution
time is therefore divided by the number of samples to provide an average
per-sample cost.

This gives a more useful comparison of throughput-oriented inference
than comparing one individual Jaccard operation with one entire
transformer batch.

### How to interpret it

-   A shorter bar indicates lower amortized latency.
-   A taller bar indicates greater computational cost per evaluated
    sample.
-   The difference illustrates the additional computation required for
    semantic transformer inference compared with lexical token overlap.

### Timing limitations

The experiment's transformer timing:

-   Excludes checkpoint download time.
-   Excludes the separate model warm-up pass.
-   Includes tokenization and model forward inference.
-   Uses CPU execution and the configured batch size.
-   Does not represent end-to-end application latency, including
    network, storage, or service overhead.

The Jaccard timing includes tokenization and similarity computation for
each sample. Timing measurements can vary with CPU load, thread
configuration, hardware, and runtime environment.

For a rigorous performance study, run multiple repetitions and report
the median and dispersion of latency measurements. The current chart
represents one measured run.

### Research significance

This chart illustrates the computational trade-off between inexpensive
lexical matching and more computationally demanding semantic
verification.

It helps assess whether the improvement in classification performance
offered by the Cross-Encoder justifies its additional inference cost.

## Recommended order for presenting the charts in a research report

A logical presentation sequence is:

1.  **Chart 01 --- Dataset characteristics:** Establish the class
    distribution and evaluation context.
2.  **Chart 02 --- Aggregate performance:** Introduce the overall
    Macro-F1 comparison.
3.  **Chart 03 --- Class-specific performance:** Explain which classes
    account for the aggregate performance.
4.  **Chart 04 --- Absolute errors:** Show the actual number of correct
    and incorrect predictions.
5.  **Chart 05 --- Directional error analysis:** Compare
    class-conditional error patterns independently of class frequency.
6.  **Chart 06 --- Computational efficiency:** Conclude with the
    latency-performance trade-off.

## Overall interpretation

Taken together, the six visualizations provide complementary views of
the experiment:

-   Chart 01 describes the evaluation data.
-   Charts 02 and 03 describe classification performance.
-   Charts 04 and 05 describe classification errors and their direction.
-   Chart 06 describes computational efficiency.

The most important research question is not simply whether the
Cross-Encoder achieves a higher Macro-F1 score than Jaccard. It is
whether semantic inference reduces consequential citation-verification
errors, particularly cases in which contradictory evidence is
incorrectly classified as supporting a claim, while maintaining an
acceptable computational cost.

All conclusions should be limited to the dataset, split, sampling
procedure, and model configuration actually evaluated. A 100-pair
evaluation is useful for an initial controlled experiment, but stronger
scientific claims require a larger, independently validated test set and
uncertainty estimates such as bootstrap confidence intervals.
